## 关闭文件时自动保存（不弹对话框）
- 需求：录入完后点「关闭」，有未保存修改时自动存盘，不要弹出「确定关闭吗」确认框。
- 改动：`src/renderer/components/UniverSheet.tsx` 的 `handleClose` 改为 async：dirty 时先 `setStatus('正在自动保存…')` 并 `await handleSave()`，保存成功（dirty 复位）才 `onClose()`；**保存失败则保持面板打开**（不静默丢数据）。已去掉 `window.confirm`。已 `tsc --noEmit` 校验通过。(注：整程序退出 `window-all-closed`/`app.quit` 未加此逻辑，仅单文件关闭。)

## 删行后关闭不生效（脏标记漏捕获结构性变更）
- 现象：删除行 → 关闭 → 重开，被删内容还在。根因：删除/插入行/列是「结构性命令」（UI 实际派发 `sheet.command.remove-row-by-range` 等），不一定触发 `SheetValueChanged`，导致 `dirty` 没置位，`handleClose` 的自动保存不触发，文件原样保留。
- 修复：`UniverSheet.tsx` 新增 `univerAPI.Event.CommandExecuted` 监听，对结构性变更命令关键字（`remove-row`/`remove-col`/`insert-row`/`insert-col`/`delete-range-move`/`insert-range-move`/`move-range`，子串匹配以覆盖 `-by-range` 变体）`markDirty()`；`useEffect` 内 `dispCmd.dispose()` 一并释放。`saveSheet` 本就整表覆盖并清空尾部多余行，故删行可正确落盘。已 `tsc --noEmit` 校验通过。

- 校验：`tsc --noEmit` + `npm run build:renderer` 均通过。GUTTER 估算（行号表头+滚动条），宁留小缝不外溢。

## 单元格输入记忆（自动补全，类 Excel 按列自动完成）
- 需求：编辑单元格时，下方浮现「本列曾出现过的值 + 以前输入过的值」提示，辅助快速输入。
- 实现（`UniverSheet.tsx` + `index.css`）：
  - 候选源：① 当前工作表该列已有去重值 `getColumnValues(col)`（读 `getSnapshot().sheets['bill'].cellData`，复用 univerAdapter 的 SHEET_ID='bill'）；② 跨会话历史 `localStorage`（键 `bill-ac-history::<filePath>::<col>`，去重 + 截 200）。`computeSuggestions(partial,col)` 做大小写不敏感包含匹配、startsWith 优先、截 12 条。
  - 监听：`document` 捕获阶段 `input`/`keydown`/`focusout`。检测到 Univer 单元格编辑器 `contentEditable[data-u-comp='editor']`（preset-sheets-core 已打包 sheets-ui 故编辑器可用）即读其 `innerText` 作 partial、用 `getActiveRange().getColumn()` 定列，弹层定位用编辑器 `getBoundingClientRect`。
  - 交互：↑/↓ 移动高亮（preventDefault+stopPropagation 抢在 Univer 前），Enter/Tab 选中，Esc 收起，鼠标 onMouseDown(preventDefault) 选中（保持编辑器焦点）。
  - 选中 `acceptAc(v)`：把 v 写入编辑器 `textContent`+派发 `input` 事件让 Univer 更新缓冲区 → 再派发 Enter 让 Univer 提交到单元格；`acAcceptingRef` 防止程序化 input 被自身监听器误处理；同时 `pushHistory` 记历史。
  - 历史写入点：① `acceptAc` 选中时；② `SheetValueChanged` 单格提交时（`pushHistory(col, getValue())`，避开 OCR 批量/金额整列重算污染）。
  - 弹层 `.ac-popup` fixed、`z-index:2000`；卸载/失焦/空匹配即收起。
- 校验：`tsc --noEmit` + `npm run build:renderer` 均通过。

### 自动补全两处缺陷修复（17:40 左右）
- 现象：①「内容不全」——提示框在单元格下方 `rect.bottom+2` 展开，编辑框靠近窗口底部时弹层下半截被推出可视区/裁掉，只能看到前面几条；②「点击不能填进去」——`acceptAc` 直接改 `editor.textContent` 再派发合成 Enter，但 Univer 单元格编辑器是 Docs 富文本结构，富文本内部模型未必被裸 `textContent` 更新，合成 Enter 提交时落不进去。
- 修复（`UniverSheet.tsx`）：
  - 定位：新增 `computeAcPos(editorRect, itemsCount)`，估算弹层高 `min(220, n*29+10)`；若下方空间不足且上方够则翻到编辑框**上方**(`top = rect.top - h - 2`)，并 clamp 到视口内。弹层状态由 `rect` 改为 `pos{left,top}`，JSX 用 `acUi.pos`。
  - 提交：重写 `acceptAc` —— ① 仍先把编辑器 `textContent=v`+派发 `input`（尽力同步富文本模型）；② 执行 `univerAPI.executeCommand('sheet.operation.set-cell-edit-visible',{visible:false})` 关闭编辑器（按当前内容提交一次）；③ **兜底**：`setTimeout(60ms)` 后 `ws.getRange(row,col).setValue(v)` 强制把单元格写成所选值（权威写入，不受富文本模型同步差异影响）。去掉原来不可靠的合成 Enter。落盘由既有 SheetValueChanged 自动保存链路接管。
- 校验：`tsc --noEmit` + `npm run build:renderer` 均通过。
