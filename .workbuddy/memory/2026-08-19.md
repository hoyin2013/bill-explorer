# 2026-08-19

- **修复 Univer「数字以文本形式存储」报错卡死 bug**：输入日期/数量列时频繁弹出裸键名 `sheets-ui.info.error` / `sheets-ui.info.forceStringInfo` 且卡住约 1 分钟。
  根因：原代码在 `createUniver` 之后 `setConfig('sheets-ui.config', { disableForceStringAlert: true })`，① setConfig 会**整体替换** `sheets-ui.config`，把 scrollConfig/clipboardConfig/protectedRangeShadow 等默认清零；② 在预设注册后再 setConfig 时机不稳，告警仍触发。
  修复：`UniverSheet.tsx` 改为把 `disableForceStringAlert: true` + `disableForceStringMark: true` 直接传入 `UniverSheetsCorePreset({...})`（官方路径，sheets-ui 插件注册时读取），并移除 setConfig 行。Core 预设类型未声明这两个字段（类型/运行时不匹配），用类型断言传入；`tsc --noEmit` 已验证通过。重新 `npm run dev` 或 `electron:build` 后生效。

- **自动保存优化（仿 WPS/Excel 本地文件机制）**：旧实现每次改动 1 秒防抖后**整表重写真实 .xlsx**，3000+ 行时逐键卡顿且 `.billbackups` 备份泛滥。
  新机制（`UniverSheet.tsx` + `excel-memo.ts` 新增 4 个 IPC）：
  - 真实文件**定时保存** `AUTOSAVE_INTERVAL_MS=2min`（仅 dirty 时），另加**失焦/关闭/Ctrl+S** 立即落盘。
  - **自动恢复快照**：`RECOVERY_INTERVAL_MS=1min`（仅 dirty 时）把整表写入 `userData/recovery/<sha1(filePath)>.xlsx`（与真实文件分离，不写版本备份），用于崩溃后恢复未手动保存的最新修改。
  - 打开文件时 `getRecovery` 检测快照是否比真实文件新 → 弹 `window.confirm` 让用户决定恢复(`recoverFrom`，恢复前先备份真实文件)或放弃(`clearRecovery`)；真实保存成功后也 `clearRecovery`。
  - 恢复快照文件名用 `createHash('sha1')(filePath)` 唯一化，附 `.meta.json` 记原始路径。新增 IPC：`save-recovery`/`get-recovery`/`recover-from`/`clear-recovery` 及 preload/`ElectronAPI` 对应方法。
  - 改动点：`scheduleAutoSave`(1s 防抖写真文件) 已删除，改为两个 `setInterval` + `blur` 监听；`handleSave` 抽出 `getCurrentRows()`，`handleSaveRecovery` 用独立锁 `recoverySavingRef`。`esbuild` 主进程打包通过，渲染层 `tsc` 无错。
