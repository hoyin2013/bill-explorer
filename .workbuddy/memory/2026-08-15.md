## 保存时「中间空行被删除」修复（用户按月用 2 个空行作分隔）
- **问题反馈**：用户在账本里每个月数据之间有意留 2 行空行作分隔，但保存后这些空行消失了（重开文件即消失）。
- **根因**：① 前端 `SheetGrid.handleSave` 只 `pop` 尾部空行，中间空行确实传给了 `saveSheet`；② 但 `saveSheet` 把空行写成 `cell.value = null`，而 **ExcelJS 不会把"所有单元格为空"的行写入 .xlsx 文件**（稀疏存储），空行被丢弃；③ 下次 `loadSheet` 用 `ws.eachRow` 遍历，空行本就不在文件里，自然读不回来。所以"保存→重开"后空行永久消失。
- **修复**（`src/main/excel-memo.ts`）：给"数据区内的空行"写入一个**不可见占位符**，让 ExcelJS 把该行写入文件，读回时再还原成真实空行。
  - `saveSheet`：先算 `lastContent`（最后一个有实质内容行的下标）；写回时若某行全空且 `i <= lastContent`（数据区内，非末尾未使用行），则 `row.values = []` 清空后写 `row.getCell(1).value = '\u200b'`（零宽空格）。末尾空行仍按原逻辑剥离。
  - `loadSheet`：读回时若某行 **仅由占位符构成**（`arr.every(t => t === PLACEHOLDER || t.trim() === '')`，PLACEHOLDER=`'\u200b'`），则还原为 `HEADER.map(() => '')` 全空行；真正的脏空行（`arr.every(t => t.trim() === '')` 且不含占位）仍跳过。
  - **关键坑**：占位符**不能用 `\u00a0`（不间断空格）**——Node 22 的 `String.prototype.trim()` 会把 `\u00a0` 当 Unicode 空白移除，导致读回时 `arr.every(t => t.trim()==='')` 为真、占位行被误判为脏空行跳过。必须用 **`\u200b`**（零宽空格，Unicode 格式字符 Cf，不属于空白，trim 不移除），显示不可见但能骗过 eachRow 与 trim 判断。
- **验证**：写独立 round-trip 脚本（真实 ExcelJS）模拟 save→load，6 行（含中间 2 空行）保存重开后读回仍为 6 行、中间两行序号为空 —— PASS。验证后删除脚本。

- **现象**：打开文档、点了一下单元格之后，顶栏「小票识图 / AI 设置」、表头「保存 / Excel 打开 / 恢复 / 关闭」、左侧文件列表全部点不动，只有 Univer 编辑区能操作。

  1. 撑满规则收窄为精确选择器 `\.univer-container > div[data-u-comp='workbench-layout']`（**绝不能再用 `> div` 通配**）。

## Univer 日期列「输入日期变成数字」修复（所见即所得）
- **现象**：在 Univer 编辑区输入 `2026/8/15`，单元格显示成裸数字（如 `46249`）；而保存后用 Excel 打开显示的是 `2026-08-15`。编辑器与 Excel 不一致。
- **根因**：Univer 会**自动把输入的日期识别成 Excel 日期序列号**（serial），但日期列此前没有任何 `numFmt` —— 没格式的序列号就按原始数字显示。而 ExcelJS 端 `saveSheet`/`loadSheet` 一直把日期当「文本↔真实 Excel 日期（numFmt yyyy-mm-dd）」处理，所以 Excel 侧显示正常、编辑器侧却显示数字。
- **修复**（`src/renderer/univerAdapter.ts`）：把日期列（第 2 列，0 基索引 1）在 Univer 里也建成**真正的 Excel 日期列**，与 Excel 完全对齐：
  1. `rowsToWorkbookData`：日期列若可解析为日期，存成 `{v: 序列号, s:'bill-date'}`（`bill-date` 样式 = `{n:{pattern:'yyyy-mm-dd'}}`）；并在 `sheet.columnData` 把整列第 2 列默认样式设为 `bill-date`。序列号用 `datePartsToSerial` 按 `1899-12-30` 纪元计算（与 ExcelJS `dateToSerial` 同纪元，已用 node 验证 2026-08-15 两端都是 `46249`）。
  2. `workbookDataToRows`：日期列取值经 `normalizeDateValue` 归一化——序列号→`yyyy-mm-dd`，各种文本写法（2026/8/11、8-11、20260811、2026年8月15日、序列号字符串）→`yyyy-mm-dd`，非日期原样保留。这样落盘到 `saveSheet` 的永远规整文本，再由 `saveSheet` 转回真实 Excel 日期。
  3. 重构：抽出 `parseDateParts`（`parseDateText` 复用）、`datePartsToSerial`、`serialToDateText`、`normalizeDateValue`，集中所有日期解析/序列号逻辑，避免重复。
- **效果**：编辑器按 `yyyy-mm-dd` 显示日期（不再变数字），打开 Excel 也是 `yyyy-mm-dd`，所见即所得；OCR 填入的文本日期也照常归一化。已 `npm run build` 通过。

## 打开/填入后「光标跳到行位但视图不滚动」修复
- **现象**：打开文档 / OCR 填入后，光标（激活单元格）确实跳到了末尾行，但表格视图还停在原地，看不到光标位置。
- **根因（和时机无关，是 preset 缺滚动控制器）**：`UniverSheetsCorePreset` 已注册 `SHEET_UI_PLUGIN`，但**它的渲染层没有注册 `SheetsScrollRenderController`**（滚动到单元格控制器）和 `SheetScrollManagerService`（滚动管理服务）。`setActiveRange` 只改数据层选区（所以光标会跳），但自动滚动依赖 `ScrollToCellCommand` → `SheetsScrollRenderController.scrollToRange` → 找不到控制器静默失败。另外 createWorkbook 之后 render 骨架还要几百毫秒才创建完（headless 实测 ~500ms），立刻执行任何滚动命令都会 `getRenderById(...).with(...)` 抛错。
- **修复**（`src/renderer/components/UniverSheet.tsx` `setActiveAndScroll`）：不再用 `sheet.command.scroll-to-cell`（依赖缺失控制器），改用 **`sheet.command.scroll-view`**（按行索引滚动，handler 走 `SetScrollOperation`→`SheetScrollManagerService`，不依赖缺失的控制器，且自动解析 unitId/sheetId）。参数 `{ sheetViewStartRow: row, sheetViewStartColumn: col, offsetX:0, offsetY:0 }`。并在 render 就绪前做**重试**（requestAnimationFrame 后每 100ms 重试，最多 12 次）——`executeCommand` 返回 false/抛错就重试，render 一就绪即滚动成功。打开文件滚到数据末尾空行（rows.length+1），OCR 填入后滚到推进后的激活行。
- **排查验证（可复用）**：用之前那套 Electron 隐藏窗口 + `console-message(event, level, message)`（注意签名不是对象）做 DOM/命令诊断。关键发现：① 加 `UniverSheetsUIPlugin` 会报 `Plugin SHEET_UI_PLUGIN already registered`（说明 core preset 已注册）；② `sheet.command.scroll-to-cell` DELAYED 报错 `SheetsScrollRenderController2 get 0`；③ `sheet.command.scroll-view` 在给 container 真实尺寸、延迟 ~500ms 后 `DELAYED result=true` —— 证明该命令+延迟策略可行。诊断容器必须设 `width/height`（否则 render 不创建滚动服务，命令恒失败，会误判）。
- **铁律**：Univer core preset 下做"滚动到某单元格"只能用 `sheet.command.scroll-view` + 延迟/重试，**绝不能用 `scroll-to-cell`**；且诊断时必须给挂载容器真实尺寸。

## Univer 迁移后三处回归修复（金额自动算 / 空行丢失 / 插入跳视窗）
用户反馈 Univer 替换 SheetGrid 后丢失了三件旧功能，逐个修回：

### 1. 金额 = 数量 × 单价 自动计算（之前在 SheetGrid.tsx:621 有，迁移后没了）
- **恢复**（`src/renderer/components/UniverSheet.tsx`）：监听 `SheetValueChanged` 事件，取 `effectedRanges`（FRange[]，用 `fr.getRange()` 拿 IRange 的 `startRow/endRow/startColumn/endColumn`）。当变化区间**触及数量列(0基索引4)或单价列(索引5)** 时，对该区间每行调 `recomputeAmount(ws, r)`：读数量/单价，若都 >0 且金额列(索引6)未手填（空/0/NaN），则写 `金额 = qty*price`（用 `univerAdapter.fmtNum` 两位精度）。金额列本身被改不触发（避免回环）。`fmtNum` 已导出。

- **根因**：Univer 的 `cellData` 是**稀疏**模型——完全没单元格的空行不出现在 cellData 里。旧 `workbookDataToRows` 只遍历已存在的行，于是间隔空行被丢，到 `saveSheet` 时根本没 row 可写 `\u200b` 占位 → 间隔空行永久消失。
- **修复**（`src/renderer/univerAdapter.ts` `workbookDataToRows`）：改为按「最大存在行号 `maxRow`」重建**连续**行数组（1..maxRow），区间内缺失的行补成全空行，再交给 `saveSheet`（其 `\u200b` 占位逻辑会把数据区内空行写进 xlsx）。列数封顶 `COL_COUNT-1=8`。已写独立 node 脚本验证：行1-5/8-10 有数据、6-7 空缺 → 重建出 10 行、6/7 为全空，PASS。

### 3. 点「插入数据」(OCR 填入) 时视窗跳到最顶端

## 金额列改为 Univer 活公式（=数量*单价，与 Excel 双向保持公式）
- **诉求**：用户要求把「金额=数量*单价」做成 Univer 公式（而非之前存算好的数值），这样在 Excel 双击能看到 `=E2*F2`。
- **根因/关键点**：Univer 的 core preset 已注册 `UniverSheetsFormulaPlugin` + `UniverFormulaEnginePlugin`（公式引擎可用，公式是真计算不是文本）。但有两个坑：
  1. **数量/单价必须是数字**：若存成文本，`=E*F` 会做「文本*文本」→ `#VALUE!`。故 `rowsToWorkbookData` 把 数量(列4)/单价(列5)/金额(列6) 的纯数字值存成 `{ v: Number }`（文本则保留文本）；OCR 填入的矩阵也把这三列数值化。
  2. **公式存于 `f` 字段、含 `=` 前缀**：Univer `setValue('=E2*F2')` → 单元 `{ f:'=E2*F2', v:2 }`。读取金额必须读 `f` 而非 `v`（`v` 可能是计算结果甚至 `#VALUE!`）。
- **改动**：
  - `UniverSheet.recomputeAmount`：数量&单价为正、且金额列为空/0/非数字时，写活公式 `=E{row+1}*F{row+1}`（`row` 为 Univer 0 基行，+1 才是 Excel 行号；列 数量=E/单价=F/金额=G）。金额列本身有合理数值（手填或公式结果）则不覆盖——手填优先、公式自动重算。
  - `univerAdapter.rowsToWorkbookData`：`=` 开头的值 → `{ f: val }`；数值列 → `{ v: Number }`。
  - `univerAdapter.workbookDataToRows`：新增 `cellToText`，**优先 `f`**（统一补 `=`）再退 `v`，金额/任何公式列都能原样输出。
  - `excel-memo.loadSheet.cellToText`：ExcelJS 公式单元 `{ formula, result }` → 返回 `'=' + formula`（**优先于 result**），使含公式的 xlsx 打开后仍以活公式回到 Univer，不退化成静态值。
  - `excel-memo.saveSheet`：值以 `=` 开头 → `cell.value = { formula: raw.slice(1) }`（金额/数量列带 `#,##0` numFmt），Excel 打开自动计算。
- **验证**：① Electron 隐藏窗口跑真实 Univer：`createWorkbook`(数量/单价为数字)+`setValue('=E2*F2')` → 单元 `{f:'=E2*F2',v:2}`、`getValue()=2`；`workbookDataToRows` 出 `=E2*F2`；`rowsToWorkbookData` 写回 `{f}`→再读仍为 2（往返保持公式）。② 直接 ExcelJS 测试：写 `{formula:'E2*F2'}`→读回 `{formula:'E2*F2'}`→`cellToText`→`=E2*F2`→再写回 OK。`npm run build` 通过。诊断临时文件已删。
- **注意**：`indexOf` 类公式单元格在 `previewRows` 也会显示成 `=E2*F2`（仅预览小瑕疵，未处理）。

## 修复「部分表格金额列有数据、编辑框显示 0」(金额公式)
- **根因**：金额列设计为「活公式」`=E*F`。`loadSheet` 的 `cellToText`（src/main/excel-memo.ts）对公式单元格**优先返回公式串本身**（`=E2*F2`），于是 Univer 按自己的上下文重算；一旦公式引用/上下文与 Excel 不一致（如引用空单元格、数量/单价被当文本相乘），就重算成 0 → 编辑框显示 0，而原文件里明明有数。

## 分析「编辑表格关闭后搜索框卡住无法输入」
- **现象**：打开表格、编辑过单元格、再关闭 → 左侧搜索框卡住、无法输入/点击；若全程未编辑单元格则正常（搜索框可用）。
- **排除指针遮挡**：打包后 dist CSS 含 `div[id^='univer-doc-selection-container-']{position:absolute!important;width:0!important;height:0!important}`（零尺寸），且 `.app-side` 是 `z-index:1001`（高于 Univer 的 1000）。Univer 编辑期唯一额外元素是 `univer-doc-selection-container-*`，已被 CSS 强制 0×0，不挡点击；且无其它全屏 mask。故不是遮罩挡点击。
- **真因 = 焦点陷阱（focus trap）**：编辑单元格时 Univer 的 DOCS 单元格编辑器（`div#univer-doc-selection-container-*` 内 `contentEditable[data-u-comp='editor']`）抢走键盘焦点；关闭表格时 `univerAPI.dispose()` 应移除它，但编辑器容器在卸载过程中可能被 `_ensureHostContainer` reparent 到 `document.body`，且编辑器 render unit 未必同步 dispose，导致这个隐藏输入框残留并持续吞掉键盘事件 → 搜索框“卡住无法输入”。仅编辑后才出现，与现象完全吻合。
- **修复**：① `UniverSheet` 卸载 cleanup 里 `univerAPI.dispose()` 之后，强制 `document.querySelectorAll("div[id^='univer-doc-selection-container-']")` 逐个 `remove()`，若其 `contentEditable` 仍持焦点先 `blur()`；② `App.tsx` 的 `onCloseMemo` 在关闭后 `requestAnimationFrame(() => searchRef.current?.focus())` 把焦点交还搜索框，保证可用且符合“关闭后焦点定位搜索框”的预期。
- 渲染层 tsc 对改动文件无报错。
