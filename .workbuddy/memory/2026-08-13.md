## YOLOv8 小票检测 + 逐张 AI 识别（检测增强）
需求：models/ticket_detect.pt 是自己训练的 YOLOv8 小票检测模型，可框出每张小票边界。在此基础上有针对性地逐张裁剪、再用 AI 识别每张的人名与内容，提高识别率；同时在前端预览上用矩形框标出边界。

### 架构
主进程 spawn Python（ultralytics 加载模型）检测 → 返回每张票的框（预览缩放图像素坐标）+ 裁剪 base64 → 主进程对每张裁剪图调用视觉 AI（带人名清单、人名修正）→ 合并结果。检测输入用 `readImageBase64` 的缩放后 JPEG（maxWidth 1600），故框坐标天然对齐预览、裁剪图直接喂 AI。模型/Python 不可用时自动回退整图识别，不崩溃。

## 三项体验修复：快速模式 / 设置界面拖拽误关 / 提示词优化
### 1. 快速模式（关闭思考/reasoning，加速响应）
背景：模型（多为 OpenRouter 推理模型）默认走 thinking/reasoning，首 token 与整体很慢。
改动：
- `ai-service.ts`：`AIConfig` 增 `fastMode?`；`recognizeReceipt` 在请求体加 `reasoning: { enabled: false }`（OpenRouter 统一参数，跳过推理直接出答案）。若服务端拒绝该参数（非 OpenRouter 严格接口），检测 message 含 `reasoning` 时自动去掉该参数重试一次（兼容）。
- 默认开启：store schema `aiConfig.fastMode` 默认 true；`getSettings/saveSettings` 透传；`types.ts` 与 `SettingsModal` 初始 `fastMode:true`；设置界面 AI 配置区新增「快速模式（关闭思考/reasoning）」勾选框（默认勾选）。
### 2. 设置界面「拖拽全选文本时整个界面消失」bug
根因：遮罩层 `onClick` 用 `e.target===e.currentTarget` 判定关闭。当在小票文本框内 mousedown、拖拽选区后在遮罩上 mouseup 时，click 事件的 target 是两者的公共祖先（即遮罩本身）→ 误判为点击遮罩 → 整个设置界面关闭。
修复（`SettingsModal.tsx`）：新增 `backdropMouseDown` 状态，`onMouseDown` 仅当「按下点就是遮罩」才置 true；`onClick` 仅在 `backdropMouseDown && e.target===e.currentTarget` 时关闭。即「按下在遮罩且松开也在遮罩」才关，拖拽选区不再误关。
### 3. 提示词优化（DEFAULT_PROMPT / SINGLE_TICKET_PROMPT 同步）
- 新增规则6：一张小票多个商品常「共用」同一单位/数量（手写只写一次）→ 必须把共用单位/数量**代入（继承）**到每个未单独写明的商品行，禁止因"只写了一次"就置 null；仅当某商品确实不适用才允许 null。unit/count 字段说明同步强调沿用共用值。
- 新增规则7：调货人（供货人/经手人）与 备注（remark）字段一律置 null，不填任何内容，也不用「无」/「-」占位。
- 同步移除代码里把 `#序号` 注入 `remark` 的逻辑（ai-service.ts 逐票合并处、ImageWindow.tsx 单张识别处），使 备注 真正留空；小票序号改由 `tickets[].index` 承载。

## 识别慢+耗 token 优化 + 调货人修复 + 模型推荐
用户反馈：识图命中好，但①调货人要留空 ②识别很慢很耗 token ③用的 qwen3.8-max 求更合适模型推荐。
### 根因
- 慢/耗 token 主因：qwen3.8-max（DashScope 真模型）**enable_thinking 默认 true**（思考模式），产生大量 reasoning token。
- 调货人：UI「调货人」列绑定 `r.person`；模型有时把票面「调货人/供货人」写入 person 覆盖真正的客户名。
- token 次因：单票裁剪图以高分辨率送视觉模型。
### 改动
- `ai-service.ts`：`recognizeReceipt` 在 fastMode 下请求体同时加 `enable_thinking:false`（DashScope/Qwen 顶层参数，已在帮助文档确认 top-level）+ `reasoning:{enabled:false}`（OpenRouter）；被拒时 message 含 reasoning|thinking|enable_thinking 则去掉重试。
- token：`image-service.ts` 新增 `downscaleImageBase64(b64,maxDim=1280,quality=80)`；逐张识别与单张识别前降采样；`MAX_TOKENS` 8192→4096，单票 `MAX_TOKENS_CROP=2048`。
- 调货人：`normalizeRows` 中 `person = rec.name || rec.person`（客户名 name 优先，避免 supplier 覆盖）；提示词规则7 强化「严禁输出 person/调货人/供货人/经手人 字段，调货人信息一律忽略」，新增规则8「输出仅含 name/date/items/remark 四字段」。
- `SettingsModal.tsx`：模型改为「预设下拉(qwen-vl-plus/qwen3-vl-plus/qwen3-vl-flash/qwen3.8-max/qwen-max/gpt-4o-mini)+模型ID输入框」；新增推荐提示文案。
### 模型推荐结论
- 本场景（中文手写小票 OCR+结构化）用专门视觉模型比通用旗舰思考模型更便宜更快：首选 `qwen-vl-plus`（性价比最高），量大用 `qwen3-vl-flash`（最快最便宜），需更高精度用 `qwen3-vl-plus`。仍用 qwen3.8-max 时务必关思考（已自动）。
### 验证
- `rm -rf dist && npm run build` 通过；`dist-electron/main.js` 含 enable_thinking(2)、downscaleImageBase64(3)、MAX_TOKENS_CROP(3)；`main-C3sIGgNI.js` 含 model-preset / qwen-vl-plus。
- 说明：qwen3（如3.8-max）思考模式关闭用 `enable_thinking:false`（top-level，非 extra_body）；qwen3-vl 系列也支持该参数。

## 提示词精简(去调货人/备注)+日期统一+布局/分栏+检测旋转闪动修复
用户反馈：①提示词去掉调货人、备注 ②日期第一张填入后后面都参照第一张修正（同图小票大概率同一天、最多差几天）③识图窗口与主窗口等高靠右、图片列表/预览左右宽度可调 ④点检测小票时画面会"旋转一下"。

### 检测旋转闪动原因
