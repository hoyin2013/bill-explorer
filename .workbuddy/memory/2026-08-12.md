## 修复"点保存后内容被清空 / 保存成空 Excel"的 bug
现象：打开带数据的 xlsx，点"保存(Ctrl+S)"后重新打开，内容丢失、像空表。
根因：`src/main/excel-memo.ts` 的 `saveSheet` 用 `removeWorksheet + addWorksheet` 重建工作表；新建表被追加到末尾，导致文件里其它表（如"目录/封面"）升到 `worksheets[0]`。而 `loadSheet`/`previewRows` 只读 `worksheets[0]`，于是下次打开读到空表 → 误判"内容被清空"。多 sheet 文件必现（已用 exceljs 4.4.0 复现确认）。
修复：
1. `saveSheet` 不再重建工作表，改为在原数据表上覆盖写（仍写表头 + 数据行）。
2. 新增 `pickDataSheet(workbook)`：按首行匹配 9 列账单表头最多的表选为数据表，用于 `saveSheet`/`loadSheet`/`previewRows`，兼容数据不在第一张表的情况。
3. 尾部脏行清理：原来用 `spliceRows` 删尾部行，但 exceljs 4.4.0 的 `spliceRows` 删除分支要求"删除区间之后还有行"，对**尾部行无效**（实测不改变 rowCount、旧数据仍写入）。改为对 `lastNeeded+1 .. rowCount` 的每行执行 `ws.getRow(r).values = []`，空行不写入文件、rowCount 自然收敛（已复现验证：单/多 sheet、数据在第2张、尾部脏行 4 场景均数据完整且尾部收敛）。
验证：node 复现脚本 4 场景全过；`tsc -p tsconfig.electron.json --noEmit` 无新增错误（原有 NonSharedBuffer/findCell 等严格告警为历史遗留，不影响 Vite/esbuild 构建）。

## 新增"异常超大文件拦截，防止打开卡死"
需求：预防不规范 Excel（末尾大量空行、或在百万行位置残留一个孤立数字）导致 `ws.rowCount` 达百万级，`loadSheet` 逐行读取上百万行把程序卡死；此类文件直接弹窗提示、不打开。

### 根因确认
- 用 exceljs 实测：在 row 105000 写 1 个孤立值，`load` 后 `ws.rowCount === 105000`（ExcelJS 把最高行号计入 rowCount）。`loadSheet` 原逻辑 `for (r=dataStart; r<=lastDataRow; r++)` 会实例化百万行 → 卡死；`previewRows` 的自底向上扫描同理会卡。

### 改动（仅 `src/main/excel-memo.ts`）
- 顶部新增 `import { dialog } from 'electron'` 与常量 `SAFE_MAX_ROWS = 100_000`。
- `loadSheet`：`pickDataSheet` 之后、`headerLabels` 之前，若 `ws.rowCount > SAFE_MAX_ROWS` → 调 `dialog.showErrorBox('文件过大，已阻止打开', ...)`（原生弹窗，try/catch 包裹）并返回 error（含实际行数、清理建议）。**只读取 O(1) 的 `rowCount`，不触碰任何单元格**，故不会卡。
- `previewRows`：同样阈值拦截，超阈值直接返回 error（不弹窗，避免悬停预览反复弹窗），跳过自底向上百万行扫描。

### 验证
- node 脚本复现：写入 row 105000 孤立值 → `rowCount=105000`、guard 触发 `true`，确认判定前提成立。
- `npm run build:electron` 成功，`SAFE_MAX_ROWS`/`showErrorBox`/`异常超大` 已进入 `dist-electron/main.js`。
- 说明：阈值 10 万行对"小票/账单"场景足够宽松（真实数据不会到这量级），又能在百万行病理文件时阻断；如需放开可在常量处调整。
