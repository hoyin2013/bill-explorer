## 账单录入体验改造：类 Excel 整表网格编辑器
- 需求：用户希望像 Excel 一样直接编辑整张表，快速录入；列数固定 9 列不动；打开时光标定位底部空行；日期格点一下出日期选择器；复制粘贴（含从 Excel 粘贴整块）；保存=覆盖更新而非追加；处理 Excel 尾部大量空行。
- 实现：
  - 新增主进程 `loadSheet`(全量读为字符串矩阵，跳过尾部空行，日期转本地 yyyy-mm-dd) 与 `saveSheet`(重建第一张表写回，彻底清除尾部空行，按列类型写日期/数字/文本)。`saveSheet` 用 removeWorksheet+addWorksheet 重建，规避 ExcelJS rowCount 不缩减问题；多表时其它表保留。
  - 关键坑：Row.findCell 在本机 ExcelJS 版本不可靠 → 改为 `findColByLabel` 直接遍历列；`toISOString()` 有 UTC 偏移导致日期差一天 → 改用本地 `fmtDateLocal`。
  - 新增渲染组件 `src/renderer/components/SheetGrid.tsx`：固定 9 列、单元格 div 自动换行展示全部内容、选中/编辑双态、Enter 下行/Tab 右移/F2 编辑、Ctrl+C/V/X、原生 paste 解析 TSV 支持从 Excel 粘贴、日期 input 选择器（单击即开）、自动算金额(数量×单价)、日期自动顺延到下一行、列宽拖拽、合计、dirty 保护、保存覆盖写回。
  - App.tsx 用 SheetGrid 替换原 MemoPanel；preload/types/main 暴露 load-sheet/save-sheet。
- 验证：`npm run build` 通过；用临时 xlsx（含 5000 行尾部空行+日期）单测 load/save，确认尾部空行被清除(rowCount 5000→6)、表头不混入数据、日期往返正确(2026-01-05)。
- 运行：`npm run electron:preview`（构建并启动 Electron）。

## 迭代二：录入行(inputRow) 概念 + 点击即复制
- 新需求：光标定位到"最底下第一列"；预备若干空行；点单元格直接复制到录入位置；日期列——新录入行点击弹选择器，已有内容点击只复制该日期不弹选择器。
- 设计：引入 `inputRow` 状态（当前录入行），单击判定规则
  - 单元格有内容 且 行 !== inputRow → `commitCell(inputRow, c, val)` 复制到录入行同列，不弹选择器（日期同样只复制）。
  - 单元格为空 或 行 === inputRow → 该行设为 inputRow；日期列 `startEdit` 弹选择器，其它列仅选中。
  - 双击始终就地编辑（保留修改历史数据的能力）。
  - 键盘 nav/moveEdit 落到空行时自动把 inputRow 跟随过去，录入行高亮 `.entry-row` 随之移动。
- 定位修正：原 `firstEmptyRow` 在表中间存在分隔空行时会把光标错误定位到中间 → 改为 `bottomEntryRow`（最后一个有内容行 +1），真正的"最底下"。
- 预备空行：`PREPARED_EMPTY_ROWS = 12`，从录入起点往下补齐；保存时尾部空行仍会被剥离，不会写进文件。
- 滚动：`activeTdRef` + scrollIntoView，首次 `block:'center'`（能看到下方空行），之后 `'nearest'` 避免跳动；切换文件重置 `didInitialScroll`。
- 可发现性：有内容且非录入行的单元格加 `.cell-copy-src`（cursor:copy + hover 蓝底）与 title 提示。
- 验证：`tsc --noEmit` 与 `npm run build` 均通过。

## 迭代四：5 项录入提速功能（A1–A5）全部落地
- 决策：用户授权实现 A1+A2+A3+A4+A5；A3 新行预填=要；保存**不**保留原表样式（重建第一张表即可，符合之前既定方案）。
- A1 记忆式自动补全：文本列编辑时按前缀匹配本表同列历史值，弹出 `suggest` 下拉（↑↓ 选择 / Enter 下行 / Tab 右移 / Esc 关闭 / 鼠标点选停留）。`updateSuggest` 从下往上收集同列历史、去重、最多 8 项；进入文本格即通过 effect 预填建议。
- A2 复制上一行：`Ctrl+D` 把上一行整行复制到当前行（多选则各自从上一行复制）；右键"复制此行到下方"在选中行正下方插入副本并立即进入编辑。
- A3 新行预填：导航到全新空行时由 `maybeSeed` 暂存上一行 `SEED_FIELDS`(date/person/remark) 默认值到 `rowDefaultsRef`；仅在**首次录入该行**时由 `commitCell` 合并一次后清除 → 非破坏式、不污染尾部空行、不被保存成空行。
- A4 十字高亮：渲染时对 `active.r` 行加 `.row-active`、对 `active.c` 列加 `.col-active`（淡蓝底），CSS 优先级低于 entry-row/row-selected；`.td-active` 保留蓝框。
- A5 文件导入：隐藏 `<input type="file" accept=".csv,.tsv,.txt">` + 工具栏"导入"按钮，`handleImportFile` 解析 TSV/CSV（去引号）后追加到数据末尾。
- 保存增强：`rowHasSubstance`(SUBSTANCE_FIELDS=no/name/qty/price/amount) 用于剥离尾部"只有预填默认值、无实质内容"的空行，避免导航过但没录入的行写进文件。
- 踩坑：① `updateSuggest` 在 effect 依赖数组中被"声明前使用" → 把该 effect 移到 `updateSuggest` 定义之后。② 编辑态分支的 `Ctrl+D` 用到 `r`，但 `const {r,c}` 原声明在非编辑分支之后 → 把声明提到 `onContainerKey` 顶部。③ 修正前文件里误留的重复 `SEED_FIELDS`(含 unit) 与未使用的 `PREVIEW_SEED_ROWS` → 删除，只保留正确那份。
- 验证：`tsc --noEmit` 与 `npm run build`（renderer+electron）均通过。运行：`npm run electron:preview`。
- 用户澄清：「点一下复制」指的是**复制到系统剪贴板**，不是自动填进下方录入行单元格。→ 移除 `commitCell(inputRow, c, val)` 自动填充，改为 `copyText(val)` 写剪贴板 + 状态栏提示「已复制：xxx」（超 20 字截断）。目标格再 Ctrl+V 粘贴。
- 用户反馈：点新行日期格没弹出选择器。根因：原生 `<input type="date">` 仅 `focus()` **不会**展开日历，必须显式调用 `HTMLInputElement.showPicker()`。
  - 在聚焦 effect 中对 `type==='date'` 调 `showPicker()`，用 `as HTMLInputElement & { showPicker?: () => void }` 兼容旧 TS lib，try/catch 兜底（showPicker 需要用户手势）。
  - Electron 28 → Chromium 120，showPicker 自 Chrome 99 起可用，支持无虞。
  - 单元格保持空直到用户选中日期（date input 的 value 用 `/^\d{4}-\d{2}-\d{2}$/` 校验，不匹配则为空）。
- 关键交互取舍：加 `wantPickerRef` 门闩，**只有鼠标点击/双击**日期格才弹日历；键盘 Tab/Enter 导航进入日期列不弹，避免日历弹层吞掉 Tab 键打断连续录入。
- 踩坑：`handleCellClick` 的 useCallback 依赖数组里引用 `copyText`，而 `copyText` 用 const 定义在其**后面** → 依赖数组在渲染时立即求值会触发 TDZ ReferenceError。必须把 `copyText` 定义上移到 `handleCellClick` 之前。（React 组件内 useCallback 依赖顺序陷阱，易忽略。）
- 验证：`tsc --noEmit` 干净，`npm run build` 通过。

## 迭代四：日期格隐藏 "年/月/日" 占位，保持完全空白
- 用户要求：日期栏不要显示"年月日"，保留空白，只弹出日期选择器。
- 根因：Chromium 的 `<input type="date">` 空值时会**强制渲染** `年/月/日` 占位文字，无法用 `placeholder` 覆盖。
- 方案（CSS 隐藏 shadow DOM 内部字段，而非用透明 overlay，避免键盘输入完全不可见）：
  - 空值时给 input 加 `is-empty` 类，CSS 对 `::-webkit-datetime-edit` / `-fields-wrapper` / `-text` / `-year-field` / `-month-field` / `-day-field` 设 `color:transparent; opacity:0`。
  - `::-webkit-calendar-picker-indicator { display:none }` 去掉右侧日历小图标（点任意位置都会弹日历，图标多余）。
- 配套两处细节：
  - 抽出模块级 `openPicker(el)`（focus + showPicker + try/catch），聚焦 effect 与日期 input 的 `onMouseDown` 复用；`onMouseDown` 里 `preventDefault()` 后手动 focus，使**已在编辑态时再点一下也能重新弹日历**（Esc 关掉日历后不至于卡在空白格）。
  - 隐患修复：字段全隐藏会导致**键盘手动敲日期时输入过程不可见**（date input 未凑满完整日期前 value 一直为空）→ 加 `dateTyped` state，date input 的 `onKeyDown` 检测到数字键即置 true 解除遮蔽；`useEffect([active.r, active.c, editing])` 换格/重进编辑时复位。注意 onKeyDown 需在 `{...common}` 之后覆盖并手动转调 `common.onKeyDown(e)`。
- 验证：`tsc --noEmit` 干净、`npm run build` 通过，并 grep 产物 CSS 确认 `is-empty::-webkit-datetime-edit{color:transparent;opacity:0}` 与 `calendar-picker-indicator{display:none}` 已编译进去。

## 迭代五：日期列支持粘贴 + 右键菜单删除行 + Ctrl+Z 撤销
- 需求三项：日期格弹日历的同时也要能粘贴；右键菜单支持选行删除；Ctrl+Z 撤销。

### 1. 日期粘贴（`parseDateText`）
- 模块级纯函数 `parseDateText(input): string`，返回 ISO 或空串。支持格式：`YYYY-M-D` / `YYYY/M/D` / `YYYY.M.D` / `YYYYMMDD` / `YYYY年M月D日` / 两位年 `26/8/11`（补 20xx）/ 只有月日 `8/11`·`8-11`·`8月11日`（补当年）/ Excel 日期序列号（数值，1900 基准）。用 `new Date` 反查校验拦掉 `2026-02-30`、`2026-13-01`。
- **踩坑（单测抓到）**：只有月日的分支若允许点分隔，`12.5`（小数单价）会被误判为 12月5日并静默写错日期 → 月日形式**禁用点分隔**（只留 `-` `/` `月`），完整年月日形式仍支持 `2026.8.11`。单测 19/19 通过。
- 三条写入路径：
  - 非编辑态 `pasteTSV`：落到日期列的值统一走 `parseDateText` 规范化（识别不了原样保留）。
  - 日期编辑态：容器 `onPaste` 里判定 `COLUMNS[c].type==='date'` → `preventDefault()` 自行解析写入（原生 date input 不接受任意文本粘贴）。
  - 兜底：date input 的 `onKeyDown` 捕获 Ctrl/Cmd+V，用 `datePasteSeqRef` 序号做去重（paste 事件已处理则序号变化，30ms 后跳过），否则 `navigator.clipboard.readText()` 异步读取。因日历弹层可能吞掉 paste 事件，必须双路兜底。

### 2. 行选择 + 右键菜单
- 点行号 `onRowNumClick` 选整行：普通单选、Ctrl/Cmd 切换多选、Shift 以 `rowAnchorRef` 为锚点范围选。选中行样式 `.row-selected`。
- `openMenu` 计算防溢出坐标（MW=190/MH=288 与 window 尺寸夹取）；右键落在未选中行则清空旧选择（Excel 习惯）。`menuRows(r)`：右键处在选中集合内 → 整批，否则只作用该行。
- 菜单项：复制/剪切/粘贴 · 清空内容 · 上方插入行/下方插入行/删除行 · 撤销/重做。菜单项 `onMouseDown` 需 `stopPropagation()`，否则会被 window mousedown 的关闭逻辑抢先吞掉点击。
- 关闭时机：window mousedown / resize / blur / Esc / 容器滚动（`containerRef` 即 `.sheet-scroll`，overflow:auto）。
- `deleteRows` 真正移除行（行号重排），删完按 `bottomEntryRow` 补齐 `PREPARED_EMPTY_ROWS` 保证底部仍有空行可录；`clearRows` 只清内容保留行位（Delete 语义）。
- **踩坑**：行号 `onContextMenu` 里 `setSelRows(new Set([r]))` 后立刻调 `openMenu`，但 `selRowsRef` 尚未同步（React 异步更新）→ `openMenu` 会把它当"未选中"清掉。必须手动 `selRowsRef.current = s` 同步后再调。

### 3. 撤销 / 重做
- 整表快照栈（`string[][][]`），上限 `MAX_UNDO=200`；账本行数量级下深拷贝开销可忽略，比 diff/patch 简单可靠。
- `pushUndo()` 在**变更前**调用（压当前快照 + 清空 redo 栈）。所有变更入口均已接：`commitCell` / `clearCell` / `pasteTSV` / `insertRows` / `deleteRows` / `clearRows`。
- 连续键入合并：`lastCommitKeyRef` 记 `r:c`，同格连续 commit 只 push 一次；`useEffect([active.r, active.c])` 换格即置 null。**注意不能依赖 `editing`**，否则"打字直接进编辑"会被拆成两步撤销。
- 快捷键：Ctrl/Cmd+Z 撤销、Ctrl+Shift+Z / Ctrl+Y 重做；编辑态下也放行（与 Ctrl+S 同级）。工具栏「撤销」按钮 + 「删除行」按钮按 `histLen`/`selRows.size` 置灰。
- undo/redo 内部用 `containerRef.current?.focus()` 而非 `focusContainer()`，避免引用定义在后面的函数触发 TDZ。
- 验证：`tsc --noEmit` 干净、`npm run build` 通过；`parseDateText` 抽出单测 19/19；grep 产物确认 `ctx-menu`、`row-selected` 样式已编译。

## 迭代六（重要方案纠正）：日期编辑器弃用 `<input type="date">`，改文本框 + 日历按钮
用户反馈三条：① 点日期格仍无法 Ctrl+V 粘贴；② 光标不是 I 形；③ 选完日期后**下方又出现一个相同日期**。

### 根本教训：`<input type="date">` 不能兼任「文本录入框」
`showPicker()` 弹出的原生日历是 **浏览器 UI 层弹层，会接管键盘**，页面 JS 收不到 keydown / paste。
→ 迭代五那套「onPaste + onKeyDown 双路兜底」建立在「页面能收到事件」的错误前提上，**必然失效**。
→ 同时 date input 的 cursor 是 pointer，且要靠 `::-webkit-datetime-edit-*` hack 隐藏「年/月/日」占位，越修越复杂。

### 新方案（更简单且三个问题一起消失）
日期格编辑器 = `<input type="text">` + 同格右侧一个日历按钮：
- text 框天然：光标 I 形、Ctrl+V 原生可用、空就是空（**不再需要任何占位隐藏 CSS**，已整段删除）。
- 日历由一个 `.date-pick-native`（`<input type="date">`，`opacity:0` + `pointer-events:none`）承载，点按钮 / 双击格 / Alt+↓·F4 时对它调 `showPicker()`。
- **`opacity:0` 不能换成 `display:none`** —— 后者会让 showPicker 抛 `InvalidStateError`。
- **关键：openPicker 不再 `el.focus()`**。showPicker 不要求元素持有焦点；若抢走焦点，日历被 Esc 关掉后焦点卡在隐藏 input 上，光标消失且打字无效。只在 showPicker 抛错时才退回「先 focus 再弹」，此路径用 `suppressBlurRef` 防止文本框 onBlur 误退出编辑。
- 日历按钮 `onMouseDown` 必须 `preventDefault()`，否则文本框失焦退出编辑态、编辑器直接卸载。
- 输入/粘贴期间**保留原文**（否则打到一半被改写没法输入），退出编辑时由 `useEffect([editing])` + `dateEditRef` 统一用 `parseDateText` 规范化成 ISO，静默写入（不再入撤销栈）。
- 编辑态粘贴仍拦一下：只取第一段（避免从 Excel 复制的整块塞进一格），识别不了就原样填入让用户可见可改，而非静默丢弃。

### 问题③ 的元凶：自动顺延
`commitCell` 里我早前主动加的「填了日期就把下一行日期补齐」被用户视为 bug（"下方又出现了粘贴的日期"）。**已删除**。
教训：这类「贴心的自动填充」会被当成异常行为，不要默认开启。

- 清理掉的死代码：`dateTyped` state、`pasteDateFromClipboard`、`datePasteSeqRef`、整段 `::-webkit-datetime-edit-*` CSS。
- 验证：`tsc --noEmit` 干净、`npm run build` 通过；grep 产物确认 `date-edit` / `cell-editor-datetext{cursor:text}` / `date-pick-native` / `date-pick-btn` 已编译，且 `datetime-edit` 占位 hack 计数为 0。
